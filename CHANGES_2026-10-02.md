No backend source code, database schema, migrations, or database records were modified.

## Mobile frontend

The mobile application now:

- Opens the device camera through `expo-camera` and requests permission when required.
- Connects to the local model with a WebSocket using `EXPO_PUBLIC_AI_WS_URL`.
- Sends camera captures to the model and presents connecting, analyzing, no-hands, idle, translated, and error states.
- Supports front/back camera switching, automatic speech toggle, replaying speech, and ending a translation session.
- Allows a completed translation to be saved or discarded. Saved translations use the backend endpoint and the history screen loads real records.
- Uses `EXPO_PUBLIC_API_URL` and `EXPO_PUBLIC_AI_WS_URL` through `src/config/network.ts`, rather than hard-coded `localhost` URLs.
- Adds `expo-camera` and `expo-speech`, required permissions in `app.json`, `.env.example`, translation service support, and mobile i18n messages.

### Camera corrections

- Disabled `animateShutter` to remove the repeated white flash.
- Removed `skipProcessing: true` so frames preserve their correct orientation before MediaPipe processes them.
- Raised JPEG quality from `0.35` to `0.5`.
- Changed capture cadence from 60 ms to 220 ms because Expo Go cannot reliably use `takePictureAsync` at the former rate.
- Changed the preview surface to portrait geometry (`3 / 4`) and stopped forcing `4:3`, removing black side bars produced by a portrait front camera inside a landscape surface.

## AI service

- `web_service.py` continues serving the model over port 8000 through `/ws/recognize`.
- The local server was configured for LAN access with `AI_HOST=0.0.0.0` and appropriate allowed WebSocket origins.
- Origin rejection is logged to make failed mobile WebSocket connections diagnosable.
- The service was restarted and verified through `GET http://127.0.0.1:8000/health`.
- First inference no longer waits for 32 source frames. It begins after `MIN_VISIBLE_FRAMES` (10 visible-hand frames) and resamples to the fixed 32-frame shape required by the trained TensorFlow model.
- Four stable predictions are still required before committing a translation, reducing accidental output from transient motion.

## Model audit

The package currently contains these labels:

```text
__idle__, bien, buenas-noches, buenas-tardes, buenos-dias,
como-estas, gracias, hola, mal, regular
```

The dataset has 20 videos for each sign and 16 `__idle__` videos. The label count is reasonably balanced.

Added `evaluate_dataset.py` to test a trained model against videos organized as `videos/<label>/*`:

```powershell
python.exe evaluate_dataset.py --data videos --target buenas-noches
```

The audit processed all 196 dataset videos. The model correctly classified 196/196 of its own recordings. This explains why a label such as `buenas noches` can appear with high confidence in web and mobile even when wrong: the model is overfitted to the existing recordings and does not generalize sufficiently to live-camera conditions. This is not caused by the mobile WebSocket integration.

## Recommended next steps

1. Record new examples per sign with different people, lighting, backgrounds, distances, speeds, and left/right hands.
2. Prioritize `hola`, `buenas-noches`, `mal`, and `regular`, using movements similar to the live errors.
3. Keep a separate test set that is never used for training.
4. Retrain, then run `evaluate_dataset.py` against the independent test set.
5. For production latency, replace Expo Go repeated picture capture with native frame processing in a development build.
